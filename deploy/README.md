# deploy/

Server-side config that lives outside the `dist/` bundle. Everything here is
generated by `npm run build` — edit the source, not the output.

## `nginx-redirects.conf`

301s for legacy URL shapes Google still has indexed. Generated from
`src/utils/legacy-redirects.ts` by the `nginx-redirect-table` integration in
`astro.config.mjs`, so it can never drift from the slugs the site actually
builds.

The same redirects also ship inside `dist/` as meta-refresh stub pages (Astro's
`redirects` config), which means **the 404s are fixed by deploying `dist/` alone**.
Installing this file is the upgrade: an explicit `301` instead of a redirect
Google has to infer from a meta refresh, and nginx answers before the stub file
is ever read.

### Install (once)

```bash
scp deploy/nginx-redirects.conf \
    root@<host>:/etc/nginx/snippets/handmadepastaflorence-redirects.conf
```

Inside the site's `server { … }` block in `/etc/nginx/sites-available/`:

```nginx
include /etc/nginx/snippets/handmadepastaflorence-redirects.conf;
```

Then:

```bash
nginx -t && systemctl reload nginx
```

`location = /path/` is an exact match, which nginx resolves ahead of the
prefix match that serves static files — so these fire before the 404 handler.

### After a slug change

Re-run `npm run build` and re-copy the file. The list is derived, so a renamed
landing slug updates its own redirect automatically.
